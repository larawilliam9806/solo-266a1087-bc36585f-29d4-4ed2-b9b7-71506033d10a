# 卷材厚度 P95 核算台

针对「部分卷只留了测厚摘要」的场景：质检员按批号、卷号登记每卷的
**测点数、最薄值、P95、最厚值**（整数微米），也可以为单卷上传完整读数
CSV。系统据此计算整批 P95 的可行区间，并给出 **必超限 / 必不超限 / 待补明细**
三种判定。

## 运行

```bash
docker compose up --build
# 打开 http://localhost:8000
```

数据保存在命名卷 `qc-data` 的 `/data/qc.db` 中。临时明细索引写在容器的
临时目录（可用 `TMPDIR` 指向内存盘以外、空间足够的目录）。本地直接运行：

```bash
pip install -r requirements.txt
QC_DB=./data/qc.db python app.py   # http://localhost:8000
```

## 规则

* P95 定义为升序第 `ceil(点数 × 0.95)` 个读数，用整数运算
  `(95n + 99) // 100` 计算位次，避免浮点误差。
* 摘要必须能同时成立才允许登记，例如 2 点卷的 P95 必然等于最厚值。
* 单卷明细 CSV 的读数个数、最薄值、P95、最厚值必须与已提交摘要全部相符，
  才启用为核算依据；否则存档并停用，核算退回摘要。
* 换交摘要时，旧摘要作废；原明细若与新摘要不符则停用，改按新摘要核算。
* 一次判定读取并在同一事务内固化当时的有效摘要/明细快照；判定结果连同
  快照一起落库。后续改档不会改写历史判定。
* 写入失败整体回滚，原档案与历史判定保持不变；资源不足（内存/临时空间）
  导致核算或保存失败时同样不新增判定记录，已有判定照常查阅。
* 摘要从不展开为逐点读数：整批区间通过对每卷的闭式计数做阈值二分求得。
* 每卷明细在一次判定中只解码一遍。解码出的有序读数写入一个匿名临时索引
  文件，之后各阈值计数都在该文件上二分查找，因此核算的工作内存只随
  **最大单卷**的测点数增长，不随卷数或整批测点数增长。旧档案无需迁移，
  可直接核算。

## 大卷与内存

核算 12 卷、每卷 50 万点（另有一卷只有摘要）时，峰值常驻内存约 60 MB，
可在 144 MiB 地址空间限制内完成。判定只需原始明细各读一遍，且不把整批
读数保留在内存中。

## 整批区间的原理

设整批 N 个读数、P95 位次为 `k = ceil(0.95N)`。

* 整批 P95 ≤ t，当且仅当可以有至少 k 个读数 ≤ t；
* 整批 P95 ≥ t，当且仅当可以有至少 `N-k+1` 个读数 ≥ t。

对每个只留摘要的卷，能在不展开读数的前提下，用 `(n, min, p95, max)`
直接算出「≤ t 的读数最多几个」和「≥ t 的读数最多几个」（`qc.py`）。
各卷相互独立，因此求和后对 t 做二分即可得到精确的最小/最大值。
